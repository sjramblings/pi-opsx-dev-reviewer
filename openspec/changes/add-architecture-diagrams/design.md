# Design — add-architecture-diagrams

## Context

The research (two independent passes, all URLs verified) converged:

- **Mermaid is the default** — the only diagrams-as-code format GitHub renders natively in
  Markdown with no build step. PlantUML, Structurizr, and D2 all need a renderer.
- **arc42 diagram map** — §3 context, §5 building block, §7 deployment are diagram-mandatory in
  practice; §6 runtime (sequence) and §10 quality tree are conventional; §2/§9/§11/§12 are
  prose/table by design and a diagram there is an anti-pattern.
- **Mermaid `C4`/`mindmap` are officially experimental** — "syntax and properties can change".
- **Rot** — text-per-diagram still rots (Simon Brown, Diagrams-as-Code 2.0); model-based
  (Structurizr) is the anti-rot winner but needs a build step.

## Goals / Non-Goals

**Goals:**

- Require a diagram in §3/§5/§7, expect one in §6/§10, forbid one in §2/§9/§11/§12.
- Render the diagrams in the self-contained `index.html`.
- Fail the gate on a missing required diagram or an unparseable one.
- Close the architecture-writer bash-scope finding.

**Non-Goals:**

- Model-based diagramming (Structurizr). Offered as a future opt-in, not built here.
- Requiring `C4`/`mindmap`. They stay opt-in behind the stable primitives.
- Auto-generating diagram content from code. The writer authors the Mermaid; the gate checks it.

## Decisions

**Mermaid, stable primitives for the required diagrams.** §3/§5/§7 use `flowchart`; §6 uses
`sequenceDiagram`. `C4Context`/`C4Container`/`mindmap` are allowed but never required, so a
Mermaid release changing experimental syntax cannot break the BLOCK gate.
Consequence: the required diagrams are plainer than full C4, in exchange for a gate that rests on
syntax that will not move.

**Inline a pinned Mermaid runtime in the HTML (client-side render).** The page bundles a
byte-pinned `mermaid` build and renders `pre.mermaid` blocks in the browser. Chosen over
build-time SVG pre-rendering because it needs no Chromium at generation time and renders any
Mermaid the writer produces.
Consequence: the file grows by the runtime size and diagrams render on open rather than being
inert SVG; the freshness hash stays valid only because the runtime is pinned and vendored, so
the generated bytes are deterministic. Pinning is load-bearing, not cosmetic.

**Two gate checks, mirroring the three-state contract.** `diagram-presence` fails when a
required section (§3/§5/§7) has no Mermaid fence and warns for §6/§10; `diagram-syntax` runs a
validator over every fence and fails on a parse error, or reports `PARTIAL` when the validator
is not installed — never a false clean.
Consequence: a broken diagram fails closed; a machine without the validator gets a weaker signal
(PARTIAL), consistent with the existing gate tools.

**Path-gate the architecture-writer's bash.** `architect-scope` currently inspects only
`write`/`edit`. The writer's `bash` can `sed -i`/`cp`/redirect outside `docs/architecture/**`.
The guard is extended to parse write-capable shell for scoped agents and block writes outside
their allowed prefixes, reusing the `force-delegate` bash-parsing approach.
Consequence: the writer keeps bash to run the gate and the render, but shell writes are held to
the same path scope as its `write` tool; the guard file is tokenizer-fragile, so the edit is
covered by `check-extensions` and unit tests.

## Risks / Trade-offs

- **HTML size.** The inlined runtime adds weight to every generated doc. Mitigation: pin a
  single vendored copy; the page is still one self-contained file with no external request.
- **Freshness-hash flaps.** A non-deterministic runtime or a CDN-fetched build would break the
  freshness gate. Mitigation: vendor a pinned build; the render output is deterministic bytes.
- **Bash-gating false positives.** Deny-by-default shell parsing can block a legitimate command.
  Mitigation: the writer needs shell only for `just arch-lint`/`just architecture-html` and
  reads; those are allowlisted, everything writing outside scope is blocked, tests cover both.
- **Validator dependency.** `diagram-syntax` needs a Mermaid validator. Mitigation: graceful-skip
  to PARTIAL when absent, exactly like the Well-Architected lookup in `arch-lint` today.
- **Experimental-syntax drift.** If a future writer uses `C4`/`mindmap` and Mermaid changes it,
  the diagram breaks. Mitigation: required diagrams use stable primitives; experimental syntax is
  opt-in and its breakage is caught by `diagram-syntax`, not silently shipped.
